## 七、代码规模控制

| 指标 | 阈值 | 超过时 |
|------|------|--------|
| 单文件行数 | ≤ 300 行（上限以功能边界为准） | 拆分模块 / 提取函数 |
| 单函数行数 | ≤ 50 行 | 拆分子函数 |
| 嵌套深度 | ≤ 3 层 | 用 early return 平铺 |
| 函数参数 | ≤ 4 个 | 改用对象/字典参数 |
| 圈复杂度 | ≤ 10 | 拆分分支逻辑 |
| 单类方法数 | ≤ 15 个 | 拆分职责 / 提取协作者 |
| 单模块直接依赖 | ≤ 8 个 | 引入门面模块 / 调整边界 |

**落地方法**：
- 嵌套过深时，优先使用 early return、guard clause 或策略对象平铺流程。
- 分支过多时，优先用映射表、状态模式、责任链或多态拆分，不把所有规则塞进一个函数。
- 自动生成代码、迁移文件、锁文件、大型配置文件可突破行数限制，但必须标记来源，不手工维护生成内容。

**early return 示例**：

```ts
function submitOrder(order: Order) {
  if (!order.items.length) return fail("EMPTY_ORDER");
  if (!order.userId) return fail("MISSING_USER");

  return createOrder(order);
}
```

## 八、规范优先级

项目间发生冲突时，按以下顺序裁决：

1. **安全** — 不可妥协（密钥泄露、注入漏洞、权限缺失）
2. **架构** — 目录位置、依赖方向、模块边界
3. **类型安全** — 类型标注完整、禁止逃逸类型
4. **规模控制** — 文件/函数行数限制
5. **命名** — 一致性比具体风格更重要
6. **风格** — 由格式化工具自动保证，不人工争论
7. **Git** — Conventional Commits 格式
8. **测试** — 覆盖率 ≥ 80%
9. **文档** — 关键决策有记录
