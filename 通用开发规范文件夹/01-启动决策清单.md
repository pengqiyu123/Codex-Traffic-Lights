# 项目开窗期通用规范

> **定位**：新项目启动时的决策清单和脚手架模板。通用编码规范由 `~/.claude/rules/` 全局规则覆盖，此处不重复。
> **用法**：新项目开窗时，按此文件逐项确认。根据项目形态选择对应章节，跳过不适用的部分。
> **AI 专项**：涉及 LLM API、RAG、Agent、多模型路由、MCP / Skills / Prompts 的项目，必须同时参考 `06-AI产品专项规范.md`。

---

## 一、启动决策清单

新项目第一天，依次确认以下决策。每个决策点建议产出一条 ADR 或写入 CLAUDE.md。

### 1.1 第一个决策：项目形态

先确定项目属于哪种形态，再决定目录结构和架构模式：

| 形态 | 特征 | 典型例子 |
|------|------|---------|
| **本地工具** | CLI / GUI 桌面应用，无需服务端 | 自动化脚本、桌面工具、编辑器插件 |
| **库 / SDK** | 被其他项目引用，不独立运行 | pip 包、npm 包、共享库 |
| **Web 全栈** | 一个代码库同时包含页面渲染和业务逻辑 | Next.js、Django、Nuxt、FastAPI+HTMX |
| **API 服务** | 纯后端，对外暴露 HTTP/gRPC/WebSocket 接口 | REST API、微服务、Worker |
| **多产品工作区** | 多个应用/库共享同一仓库 | Monorepo、npm workspace |
| **AI / LLM 应用** | 调用模型、检索知识库、执行 Agent 工具或管理多模型路由 | RAG、LLM API 服务、Agent、MCP 工具、模型网关 |

> 大多数项目只属于一种形态。如果一个项目"既是工具又是 API"，大概率应该拆成两个项目或用 Monorepo 管理。
> AI / LLM 应用通常叠加在 Web 全栈、API 服务或本地工具之上；基础目录按主形态选择，AI 治理按 `06-AI产品专项规范.md` 执行。

### 1.2 技术栈确认

| 决策点 | 确认内容 |
|--------|---------|
| 语言与版本 | 主语言、最低版本要求 |
| 框架与运行时 | 选择框架 / 明确无框架 |
| 类型系统 | 静态类型（strict）还是动态 + 渐进标注 |
| 包管理 | pip / npm / pnpm / cargo / go modules |
| 依赖管理 | 是否锁定版本、锁文件规则、私有源配置 |
| 依赖更新 | 月度安全补丁、季度大版本评估、例外审批方式 |
| 测试框架 | pytest / Vitest / Jest / cargo test / Go testing |

### 1.3 架构决策

| 决策点 | 选项 |
|--------|------|
| 分层策略 | 按功能划分（Feature-based）vs 按职责层划分（Layered）vs 混合 |
| 模块边界 | 目录即模块 / Python package / npm workspace |
| 错误处理 | 结构化异常（code + message）/ 错误码枚举 / Result 类型 |
| 配置管理 | 环境变量 / 配置文件 / 启动参数 |
| 日志策略 | 结构化 JSON / 文本日志；字段包含 trace_id、level、event、message |
| 监控策略 | 请求耗时、错误率、队列积压、外部依赖失败率 |
| 告警策略 | P95/P99 延迟、5xx 比例、任务失败次数、磁盘/内存阈值 |
| AI 治理 | Prompt 版本、eval 集、模型路由、成本上限、工具权限 |

### 1.4 工具链确认

| 工具类别 | 选择 | 配置文件 |
|---------|------|---------|
| 格式化 | black / prettier / rustfmt | `pyproject.toml` / `.prettierrc` |
| Lint | ruff / ESLint / clippy | `setup.cfg` / `eslint.config.*` |
| 类型检查 | mypy / pyright / tsc | `pyproject.toml` / `tsconfig.json` |
| Git Hooks | husky + lint-staged / pre-commit | `.husky/` / `.pre-commit-config.yaml` |
| 包安全扫描 | npm audit / pip-audit / safety / cargo audit / trivy | CI workflow / pre-commit |
| AI 观测 | CC Switch / Langfuse / LangSmith / OpenTelemetry | trace / usage / eval 配置 |
| CI | GitHub Actions / GitLab CI / 无 | `.github/workflows/` |

**依赖管理底线**：
- 应用类项目必须提交锁文件：`package-lock.json` / `pnpm-lock.yaml` / `poetry.lock` / `uv.lock` / `Cargo.lock`。
- 库 / SDK 是否提交锁文件按生态惯例决定，但 CI 必须有可复现安装方式。
- CI 必须阻断高危依赖；中危依赖允许进入待办，但必须有处理期限。
- `.env`、私有源凭证、令牌不得进入仓库；只提交 `.env.example`。
